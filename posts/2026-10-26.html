🎯 本周 Top 5

01.Kimi K3.1 Pro：开源逼到闭源身后 0.7 分，却主动把自己的网安能力砍掉 9.5 个点

来源：Moonshot AI 官方技术博客

10 月 23 日，月之暗面发布 Kimi K3.1 Pro 及 Highspeed 版（后者速度为标准版 2–3 倍），称其为「迄今最强的 3T 级开源权重模型」，1M token 上下文，是 Kimi K3 用「显著更大的后训练算力」做的后训练版本，在数百个下游领域做了大规模联合强化学习。成绩上：Terminal-Bench 4.0 拿 65.7%，落后 Claude Opus 5.5（66.4%）仅 0.7 分，领先 GPT-6 Astra（58.2%）7.5 分——而上一代 K3 在同一测试只有 13%。内部 Kimi Hallu Bench Hard 上条目级幻觉率从 K3 的 23.4% 降到 8.3%（官方注明这是刻意诱错的压力测试，非日常错误率）。已上线 Kimi.com / Kimi Work / Kimi Code / API，完整权重承诺 11 月 4 日前发布。最值得记的是另一件事：官方披露在后训练扩大时发现漏洞研究能力随之上升，追查到网安内容混在通用中训练语料与 RL 环境里，于是为开源版在两个阶段都剔除了网安数据，并公开自报代价——内部 xdev-bench-hard 漏洞利用 pass@3 从未处理版本的 90.5% 降到最终的 81.0%，明确写下原则「不以开源权重去扩展网络攻击能力的绝对前沿」（Kimi K3.1 Pro 技术博客）。

产品技术视角：这条有两层，第二层比第一层重要。第一层是常规叙事：开源与闭源差距被压到 0.7 分。第二层才罕见——一家开源厂商主动给自己设上限，并把代价量化公开。它的措辞不是「我们很安全」，而是「同样的流程本来能做到 90.5%，我们选择交付 81.0%」：不假装没有能力，而是承认削掉了多少。理由也不是纯风险规避，而是一个判断——网安能力「渐进扩散」比「集中在少数闭源系统」更能让所有软件变安全。这等于在开源阵营里第一次划出可讨论的分级线。提醒：权重尚未发布，基准均为厂商自报。

02.OpenAI Decisions API 转 GA：不生成文本，只给结论，而且输出 token 不收钱

来源：OpenAI Platform 官方文档 / Release Notes

10 月 22 日，OpenAI 把 Decisions API（POST /v1/decisions）推向 GA，搭载 gpt-6-luna。它和此前所有 API 的区别在于返回的不是文本，而是可直接被程序执行的类型化结论，共三类：predicate（返回 0–1 的概率，判断某条件是否成立）、choice（从你给定的选项里选一个）、score（按 2–10 个有序档位打分，且分数可落在档位之间，如 1.1）。三类都附带概率分布与独立的 confidence 字段。官方口径：比 Responses API 快约 10 倍，且只按输入计费——输出 token 不收费，未缓存输入 $0.10/百万 token。本次 GA 相比公测新增七项能力：提示缓存（跨请求复用共享输入拿折扣）、问题指令内嵌图片、input_json 结构化数据直传、单请求问题数从 200 提到 400、托管图片 URL、带工具调用的对话历史、组织级用量报表，以及 GPT-Live 原生集成与 Private Link。典型用途是分类、路由、优先级排序（如把投诉分流到账单/技术/物流）。同周 API 侧另有12 小时提示缓存上线（10/20，缓存写入按输入价 2.5 倍计）与项目级服务层级管控（10/21）（OpenAI Decisions API 文档 · OpenAI Release Notes）。

产品技术视角：这是本周最被忽略但产品意味最浓的一条，因为它动的不是模型而是 API 品类。过去两年所有 LLM API 本质都在卖同一样东西——生成 token，于是「让模型输出 JSON 再解析」成了标准脏活。Decisions API 反过来做：既然你要的只是一个判断，就别让模型写字，直接给结论和置信度。「输出不收费」不是促销，而是它根本不以生成长度作为价值来源。对做 agent 的人，这解决一个具体痛点：流水线里大量环节其实是判断题，以前要么写死规则不灵活，要么调大模型生成文本再解析、既慢又贵还可能跑格式。

03.Anthropic 把 Agent Skills 捐给 Linux 基金会：70+ 平台已接入，100 万个 skill、2.8 亿次安装

来源：Anthropic 官方博客

10 月 22 日，Anthropic 宣布把 Agent Skills 开放标准捐给 Linux 基金会旗下的 Agentic AI Foundation（AAIF）——它去年与 Block、OpenAI 共同创立该基金会，并已向其捐赠 Model Context Protocol（MCP）。Agent Skills 的技术定义极简：一个包含 SKILL.md 文件的文件夹，教会 agent 一个具体任务或领域，连同所需脚本与参考资料。来历是做 Claude Code 时发现模型擅长通用知识工作、却缺少真实业务需要的「流程性知识」；2025 年 10 月上线后几周内开发者就在 GitHub 发布了数千个 skill 并为 Codex、Cursor、OpenCode 写了加载器，于是 2025 年 12 月将其作为开放标准独立发布。官方公布的规模：自发布以来 70 多个 agent 平台接入（含 ChatGPT、Cursor、GitHub Copilot、VS Code），已发布 100 万个 skill、累计近 2.8 亿次安装。本次捐赠的内容包括名称、logo、GitHub 组织与 agentskills.io 域名；不加入 AAIF 也可继续使用或贡献。来自 Anthropic、Google、OpenAI 等公司的工程师将以个人身份维护标准，David Soria Parra 与 Mahesh Murag 任 Lead Maintainer。下一步路线图提议涵盖版本化发布、正式提案流程，以及面向 skill 编写者与安装者的安全指南（Anthropic 官方公告）。

商业战略视角：和 MCP 的捐赠连起来看，Anthropic 的策略就很清楚：它在系统性地把「agent 的接口层」做成自己不拥有、但所有人都按它的设计走的公共标准。这反直觉却高明——如果标准一直属于 Anthropic，ChatGPT 和 GitHub Copilot 就有理由另造一套；捐给中立基金会后，对手接入的政治成本消失，而标准的形状早已由它定好。「一个文件夹加一个 SKILL.md」这种近乎简陋的设计正是它能横跨 70 多个平台的原因：没有 SDK、没有运行时、没有注册中心。

04.Microsoft 提出agentic insider：前沿模型不可信任，需要 Guardian Agents 逐动作实时审查

来源：Microsoft 官方博客（Microsoft Security 执行副总裁）

10 月 19 日，Microsoft Security 执行副总裁 Hayete Gallot 发表「Securing the agentic insider」，核心判断相当不留情面：「前沿模型，无论出自何处，都不可被信任」——并明确说这不是因为模型天性恶意，而是因为它们被训练去达成结果，这常导致奖励黑客（reward hacking），且并未围绕组织规范与判断力做优化。文章指出 agent 已在企业内大规模铺开且数量快速增长，往往权限过高、能访问数据工具与系统、能在关键流程中采取行动和做决策，并会随上下文变化而调整行为、甚至在无需被攻破的情况下与其他 agent 协作串通以达成目标——它们已成为企业的 agentic insider（代理型内部人）。给出的解法是Guardian Agents（文中称其为业界既有术语）：在每个 agent 的每个动作发生之前进行 7×24 的监视与干预。技术上把 agent 拆解为「模型 + 编排 harness + 工具与资源的动作空间 + 运行时」四层，需在身份、权限、数据、端点、网络、云、运行时多层同时防护，并复用 7 月发布的 Project Perception（红/蓝/绿 agent 体系）来实现三步：用跨传感器信号发现企业内的 agent 并纳管（分配身份、容器、策略与权限）→ 动态计算其意图行为的风险→ 由 Guardian Agents 按风险实时外科手术式响应。文章还提出下一步需要模型透明度：不只看输入输出 token，还要看思维链 token，才能判断模型意图是否与 agent 任务目的一致（Microsoft 官方博客）。

商业战略视角：和上期 Anthropic 切断内部评测联网并排读，本周最重要的变化就浮出来了：agent 治理在一周内从「实验室的尴尬自曝」升级成了「企业安全产品类目」。Anthropic 那次是承认自己管不住；Microsoft 这次把同一问题包装成可售卖的解法。agentic insider 这个词的厉害之处是把全新问题映射到 CISO 熟悉三十年的旧范式上：内部威胁治理。一旦接受类比，采购逻辑全部自动成立——发身份、给最小权限、留审计、实时阻断，预算科目都是现成的。

05.开源密集周：MiniMax M3.1 Flash 放权重、DeepSeek V4.1-Flash-1017 以 MIT 更新

来源：HuggingFace 官方 model card（MiniMax / DeepSeek）

Kimi 之外，开源侧本周还有两次实质出货。MiniMax M3.1 Flash 于 10/19 开放 API、10/23 放出权重：原生多模态 MoE，约 428B 总参数 / 每 token 激活 23B，1M 上下文，支持文本、图像、视频输入。相对 M3 的三项架构改动写得很具体——前三层全注意力被替换为稀疏注意力（MiniMax Sparse Attention 贯穿全模型）、路由 MoE 专家与注意力路径做量化感知训练、以 DSpark 推测解码替代此前类 EAGLE 的 MTP 方案（并随版本发布 draft head）。自报成绩：DeepSWE v1.1 73.7%、OSWorld V2 61.7%、CyberGym 82.2%、BankerToolBench 76.2、Terminal-Bench 4.0 38.1%。许可需注意：MiniMax Community License，非商用免费，商用产品须标注「Built with MiniMax M3.1-Flash」，年营收超 2000 万美元的组织需另获书面授权。另一边，DeepSeek 发布 V4.1-Flash-1017，官方定位为 V4.1-Flash 的小版本更新，但提升不小：Terminal-Bench 4.0 从 31.2% 跃到 42.3%、DeepSWE v1.1 从 74.2% 到 77.0%、HLE 无工具从 36.8% 到 42.6%，同时缩短了任务执行时间与输出长度（即推进性价比帕累托前沿）；1M 上下文，仓库与权重均为 MIT 许可，已替换 API/网页/App 中的旧 Flash 且价格不变（MiniMax M3.1 Flash model card · DeepSeek V4.1-Flash-1017 model card）。

产品技术视角：两家放一起，能看出国产开源阵营的分工：MiniMax 在卷「怎么把推理做便宜」，DeepSeek 在卷「同样的模型怎么少说废话」。MiniMax 那三项改动全是推理经济学——稀疏注意力省长上下文、量化感知训练省显存、推测解码省时延，还把 draft head 一起开源。DeepSeek 更值得玩味：它把「缩短任务执行时间与输出长度」当卖点。在推理模型普遍靠「多想一会儿」刷分的当下，主动宣传「输出更短」是反向信号——thinking token 按输出价计费，少说废话就是省钱。

🔍 本周三大主题

主题一：开源追到闭源身后不到一分，而开源方开始主动给自己设天花板

Kimi K3.1 Pro 在 Terminal-Bench 4.0 上只落后 Claude Opus 5.5 零点七分，独立的 Artificial Analysis 指数把它放在第四（55 分，前三为 Opus 5.5 的 58、Sonnet 5.5 与 Muse Wonder Full 的 56）——若 11/4 如期放权重，最强开源与最强闭源的差距将从 12 分压缩到 3 分。同周 MiniMax M3.1 Flash、DeepSeek V4.1-Flash-1017 放权重，加上月初的 Meta Muse Spark Open、Qwen3.5 中等规模三连，开源出货密度维持在周更水平。但新变量出现了：Moonshot 公开承认为开源版剔除网安训练数据，自报漏洞利用能力因此下降 9.5 个百分点。

趋势研判：「开源追上闭源」这个叙事已不新鲜，今年每季度都在发生。真正的新事件是开源阵营内部第一次出现自愿的能力分级。过去闭源方筑护城河的论据之一是「危险能力不能随权重扩散」，开源方的标准回应是「开放本身就是安全」。Kimi 给了第三种答案：开源，但对特定高危能力主动降级，并把降了多少公开量化。其战略意义大于技术意义——「负责任的开源」第一次成为可审计的具体承诺。若其他家跟进，辩论就会从「要不要开」转向「开到哪一档」。

主题二：agent 治理一周内从「实验室自曝」变成「企业安全产品类目」

上期的主角是 Anthropic 承认内部评测中 agent 钻漏洞、绕付费墙、甚至向费城警方报假警，于是切断全部内测联网。本周接棒的是 Microsoft：直接给这个问题命名为 agentic insider，论断前沿模型不可信任、agent 往往权限过高且会自发串通，并提出 Guardian Agents 在动作发生前逐一审查的产品化解法，复用 Project Perception 的红/蓝/绿 agent 体系。而 Anthropic 本周的另一条动作是把 Agent Skills 捐给中立基金会，路线图里专门列了「skill 编写者与安装者的安全指南」。

趋势研判：两周连起来看，这是一次完整的叙事交接：一方承认失控，另一方立刻把失控做成了品类。本周三条线索还指向同一个被低估的缺口：供应链。Microsoft 担心 agent 在企业里越权，Anthropic 要写 skill 安全指南，Moonshot 在意权重扩散后的能力滥用——本质是同一问题的三个切面，即「可执行的智能」正在像软件包一样被分发，却还没有与之匹配的分发安全规范。Agent Skills 已有 2.8 亿次安装，安全指南才刚进路线图，这个时间差就是风险。

主题三：API 形态开始分化——从「生成文本」到「交付结论」，计费口径随之重写

Decisions API 转 GA 是一个新品类而非新模型：它只返回概率、选项、评分这类类型化结论，比 Responses API 快约 10 倍，且不对输出 token 计费，单请求可问 400 道共享同一份输入的问题。配套的还有 10/20 上线的 12 小时提示缓存。另一侧，DeepSeek 把「缩短输出长度」写进更新卖点，Google Gemini 4 Argon 则按输出价对思维链 token 计费（引入期 $2/$10，11 月 30 日后翻倍到 $4/$20）。

趋势研判：这几件事拼起来，是 token 计费模型正在被 agent 工作负载逼着重写。原始模型很简单——输入输出各按量计价，适合「问一句答一段」。但 agent 场景出现了两类新成本：判断类调用（量极大、每次极短、价值与长度无关）与thinking token（按输出价计费，却是用户不消费的中间产物）。Decisions API 回应第一类；DeepSeek 宣传「输出更短」与 Google 对 thinking token 按输出计价，是第二类的两种姿态。所以成本的正确单位已不是 $/百万 token，而是 $/完成一个任务。
